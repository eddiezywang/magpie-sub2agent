## Context

桌面主窗口和托盘面板共享嵌入式网页及组件；内网版通过资源打包转换注入专属样式。认可的参考是 `design-preview/glm/index.html`，但其示例数据和交互不是产品契约。GUI 与供应商契约分别见 `docs/subsystems/gui-shell.md` 和 `docs/subsystems/providers-accounts.md`。

## Goals / Non-Goals

**Goals:** 内网版所有保留页面、主窗口与托盘采用一致的浅色/深色像素复古视觉；保留既有交互；隔离预览、分阶段审查。

**Non-Goals:** 不修改后端 API、供应商认证、账户/配置数据、网关、插件机制、Sessions 权限或上游 Magpie；不移除浏览器管理服务或修改其已保存值。

## Decisions

1. 以内网专属样式和受控展示结构为优先。通用组件沿用现有状态和事件；仅在保持交互语义和键盘操作时调整前端结构。避免直接复制样稿的模拟交互。
2. 供应商继续纵向排列，横向卡片外观；展开、切换、未保存内容、添加和认证行为逐项对照原版，不新增确认流程或展开限制。多列卡片暂不实现。
3. 主窗口、托盘面板都采用统一组件；浅色以暖白和蓝色为主，深色建立配套方案，保留显式及系统主题切换。像素 S 与现有供应商图标保持来源，必要时只修复可读性。
4. 核对实际内网浏览器管理配置入口后仅隐藏该选项。入口已隐藏则不新增改动；隐藏不改变已保存值、远程服务、命令或登录回调。更新 GUI shell 文档中受影响的可见性契约。
5. 每阶段使用模拟数据和拦截写请求的本地预览及 Playwright；预览持续热更新，用户可随时审查并提出调整，开发不中断等待。截图只含合成或脱敏数据，发布到既有评审站；测试覆盖 Chromium、WebKit、项目要求语言及相应视口。

## Risks / Trade-offs

- [共享样式影响控件、弹窗或拖拽] → 基于真实页面、空态、展开态和键盘交互逐页验证；避免宽泛选择器。
- [系统深色被浅色覆盖] → 分别检查显式浅色/深色及系统浅色/深色，断言计算样式和可读性。
- [预览与实际打包不一致] → 验证真实内网打包结果和非内网构建隔离，而非只在测试中注入 CSS。
- [真实账户与运行实例受影响] → 仅用隔离数据和模拟 API；不使用现有应用做写入验证，不发布凭据。
- [看起来接近样稿却改变原有行为] → 在改动前记录原行为，对照现有测试及真实 DOM；必要时放弃影响交互的视觉方案。

## Migration Plan

在 `feature/intranet-retro-glm` 上按阶段实现、验证、提交并推送。不要替换正在运行的应用；评审通过后再按既有流程构建发布。回滚对应视觉与设置可见性提交即可，不迁移账户或设置数据。
