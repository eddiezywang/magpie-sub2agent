## Context

- [用量查询](../../../internal/gui/usage.go)已有总览、按供应商过滤的热力图和请求接口。现有查询分别返回总时间序列和模型汇总，缺少时间桶与模型的交叉数据。
- [智汇通统计](../../../internal/usage/token_trend.go)使用当前网关账本，区分已记录 Token 与其它来源。缓存读写独立于输入，推理 Token 已包含在输出。
- [TIG 窗口记录](../../../internal/gateway/tig_quota.go)按供应商、API Key 指纹和智谱渠道持久化。当前供应商 JSON 的窗口读取只覆盖单个启用 Key。[服务端报表](../../../services/usage-server/src/tig-plans.js)按用户名合并，并提供滚动估算和参考额度。
- [WorkBuddy MaaS](../../../internal/usage/workbuddy_points.go)已有基于计费规则的本地估算。[WorkBuddy CIB](../../../plugins/sub2agent/workbuddy-cib.mjs)读取 `credit`、`limitNum` 和可选的 `cycleResetTime`。重置时间原文目前拼在展示文字中，周期长度和格式化时间未结构化。

## Goals / Non-Goals

第一版接通四个供应商的三种视图，复用真实账本和额度来源。窗口探测使用真实请求的 429 和现有额度查询。范围排除累计使用时长、跨设备按 Key 统计、智汇通积分、主动制造 429 和新账单系统。现有公开发行版、路由退避和上报隐私契约继续沿用。

## Decisions

### 界面和筛选

按实际供应商配置识别四个页签，已配置但无记录、凭据过期或查询失败时保留页签并显示对应状态。供应商切换保持当前三视图选项，页签消失时回到首个可用供应商，全部未配置时折叠整个面板。保留其下的原生网关概览。默认进入「用量」。TIG 渠道独立于视图切换；选择某把 Key 只作用于该 Key 的额度和估算，网关 Token 图表明确标注自身统计范围。

### TIG 窗口与 Key

从正常流量中被动采集，不主动调用以触发 429。复用现有智谱渠道标识、额度错误解析、Key 指纹和本地持久化规则。接通按启用 Key 读取窗口的接口，复用现有脱敏标识或名称，默认第一把启用 Key。兼容单 Key 已有记录，两个窗口独立更新。窗口可处于未知、从上游 429 确认的恢复时间、恢复后首次成功推得的下一窗口估算等状态。展示已知的时间字段，无法确定的起止留空，过期的恢复时间不当作有效窗口。

首次记录到成功请求，或该 Key 的五小时窗口已到期时，下一次成功请求开始新的五小时本地估算窗口。窗口内的其它请求沿用同一起点。上游 429 仍提供独立的恢复证据；周窗口仍依赖该证据。积分的界面数值四舍五入为整数，计算使用原始精度。

本地积分以请求实际使用的 Key、原始渠道模型、实际发生时间和可信费率规则计算。模型官方身份可用于显示名称，计费归属沿用原始渠道模型或现有计费别名规则。复用现有计费规则的数据源及版本，补充本地计算所需的生效时间和峰谷语义，不能凭 UI 表格重写费率。历史规则或归属缺失、原始渠道与实际回包模型冲突、缓存拆分缺失时，记录为未覆盖。按窗口聚合必须具备适用的起止和足够的账本覆盖，估算窗口须标明；否则只展示已覆盖的估算。35,000 积分为智谱 5 小时参考上限。周额度与近 7 天滚动统计分开。

同一 Key 的有效额度 429 对应的窗口直接显示 100% 和「额度已用尽」，保留单独的本地积分估算。其余 TIG 百分比按该 Key 的本地可计价积分除以参考上限，注明「当前网关估算」。窗口起点未知时，分别采用最近 5 小时和最近 7 天的滚动用量，未知日期留空。账本覆盖不足时注明缺口，有可计价记录时显示已覆盖比例。额度卡的进度在 70% 及以下显示蓝色，超过 70% 显示红色。用量概览不查询或展示按用户名汇总的服务端报表。通用 429、网关本地限流、没有窗口证据的 Retry-After 不建立套餐窗口。

### WorkBuddy 与智汇通

WorkBuddy CIB 用现有鉴权与企业额度接口获取单账号已用和总额度；多个账号各自展示。将可选重置时间原文作为可选展示字段传递，保持老版本展示兼容。只有上游明确提供起止或周期时才填对应字段。账本里的上游按请求回传积分和接口的账号额度各有来源。未回传积分的请求不补零。

WorkBuddy 企业复用 MaaS 估算，保留上游回传积分的优先级和出处；展示倍率不参与估算乘法。没有可用规则的请求不计入已覆盖估算。智汇通只统计当前网关的输入、输出和缓存 Token，保留日、7 天、30 天及账本累计，使用 K／M／B。各来源的积分、AFP、加权 Token 和普通 Token 不相加。

### 活跃度与详情

供应商级 Token 查询统一选当前网关的账本记录，应用现有删除、时区和有效请求规则，排除直接调用、上报或别处同步的记录及本地探测。复用近 53 周日汇总，为每日热力图、每周和累计趋势、日峰值及连续天数使用同一来源。趋势累计从展示区间起算，累计 Token 指保留账本全量。以有有效网关用量的自然日认定活跃。查询应区分已覆盖的零和历史不可用。

详情支持当日按小时，近 7 天及近 30 天按日，按界面时区显示日期。扩展聚合，返回总量、分模型时间桶及明细。图例开关仅影响当前图表及其可见模型合计，区间总量保持固定。缓存命中率复用已有统计语义。低峰占比只有在适用计费规则及时间归属完整时显示。系数表标出来源、单位及适用条件。

## Risks / Trade-offs

- 429 给出独立 Key 的恢复证据，无法揭示未触顶的窗口或同一 Key 在其它设备产生的消耗。标注来源和估算状态，缺失值保留空。
- 模型按时间桶聚合需要控制维度和历史读取成本。复用已有索引和按需加载，返回有限范围。页签切换和离页时忽略迟到结果。
- 当前账本保留历史有限，回收或清除之后的累计值随可用账本变化。端到端验收使用可控日期及模拟数据。

## Rollout

先实现并验证聚合、窗口与数据来源契约，再将三个视图接入原生概览。接口增量兼容，沿用现有账本和 TIG 窗口文件。以隔离配置做回归并与批准的设计预览对照。
